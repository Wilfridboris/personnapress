- (decision) AD-A1 Pull-not-push. Binds: collection pipeline + dashboard read path. Prevents: synchronous platform calls on dashboard load (latency/metered-cost/rate-ban) and building a push/webhook listener (no platform pushes these metrics). Rule: metrics collected by a scheduled APScheduler sweep writing snapshots to DB; dashboard reads ONLY stored snapshots, never triggers a platform call.
- (decision) AD-A2 External-only fetch, zero heavy compute on Droplet. Binds: workers/analytics.py, metrics integrations. Prevents: in-memory time-series/dataframe rollups on 1vCPU/1GB. Rule: retrieval is I/O-bound httpx await (like generation/transcription); aggregations computed by SQL on the snapshot table / at read time, never by loading full history into RAM; no pandas/numpy on the Droplet.
- (decision) AD-A3 Append-only immutable snapshots are source of truth. Binds: post_metrics table, repositories/post_metrics.py. Prevents: one builder UPSERTing latest-metrics onto the post row while another appends history => divergent numbers + lost trend. Rule: each poll INSERTs a new immutable row (published_post_id, platform, captured_at, raw JSONB, normalized impressions/engagements); never UPDATE a prior snapshot; 'current' = latest captured_at per post via SQL.
- (decision) AD-A4 Persist platform-native post id + permalink at publish time. Binds: publishing path (INHERITED area: services/publishing.py, workers/publish.py, per-(campaign,platform) publish record). Prevents: analytics being un-pollable because the external id the metrics API keys on was never stored. Rule: every successful publish MUST persist platform-returned post id + permalink on a per-(campaign,platform) record; harvester keys polls on it. Upstream extension imposed on publishing epic -- flag to publishing owner.
- (decision) AD-A5 Metrics capability is per-platform and asymmetric; only X + LinkedIn in v2 scope. Binds: metrics integrations, capability flags, dashboard empty states. Prevents: assuming every connected platform yields metrics (blank-polling WordPress/Webflow) or symmetric fields. Rule: metrics-capable only if platform exposes member/post-level read API -> X (public_metrics) + LinkedIn (memberCreatorPostAnalytics). Out: Webflow (no API), self-hosted WordPress (Jetpack/GA only -> deferred), Meta/IG/Threads (publishing deferred). Each integration declares capability; harvester skips non-capable; dashboard shows explicit 'not available for this platform', not zeros.
- (decision) AD-A6 Metered read cost governed by decaying cadence + per-user poll budget, logged. Binds: harvester scheduler, cost log, subscription tier. Prevents: unbounded X pay-per-use reads ($0.005 each) silently running up cost; polling forever. Rule: reads logged (reuse/extend generation_logs: platform, read_count, est cost) and bounded by a hard per-user/per-cycle poll budget checked before each sweep (like subscription enforcement). [ASSUMPTION cadence: hourly 24h -> daily 7d -> weekly to 90d horizon then stop; budget cap TBD at implementation].
- (decision) AD-A7 One new table + one publish-record field; no other schema churn. Binds: alembic migration, models. Prevents: per-platform table sprawl / metrics-column explosion on campaigns. Approval is an ops/deploy precondition, not code.

CQRS-lite: write side = sweep appends snapshots; read side = SQL rollup projections.
